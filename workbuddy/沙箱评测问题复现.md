# 专家 oe_0263434b4ac82583 沙箱评测失败：DeferExecuteTool 被权限拒绝

提交方：北京开云见山科技有限公司
资产：专家「股票估值专家」 oe_0263434b4ac82583 v1.2.0
驳回时间：2026-09-10 15:09，评级"低质量"，原因之一为"沙箱评测中表现未达审核标准"

## 结论

该专家依赖 MCP 工具 `mcp__valuescope__run_dcf`（通过包内 `.mcp.json` +
`dependencies.mcpServers` 声明）。**MCP 服务在沙箱式环境中能正常连接，但工具无法执行**，
原因不在我们的包，而在运行侧的权限配置：

- WorkBuddy 对 MCP 工具采用延迟加载：模型不能直接调用 `mcp__valuescope__run_dcf`，
  必须经 `DeferExecuteTool` 中转；
- `DeferExecuteTool` 属于需审批工具，非交互模式下无法弹出审批；
- 因此每一次工具调用都返回权限拒绝，专家无法产出任何估值结果。

**如果沙箱评测以非交互方式运行且未放行 `DeferExecuteTool`，任何依赖 MCP 的专家都会
以同样方式失败**，与专家本身质量无关。

## 复现步骤（使用 WorkBuddy 自带 CLI）

```bash
CB=/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/cli/bin/codebuddy
mkdir -p /tmp/cleanenv                     # 全新配置目录，模拟评测环境

CODEBUDDY_CONFIG_DIR=/tmp/cleanenv $CB -p \
  --plugin-dir <专家包目录> \
  --agent valuescope-dcf-analyst \
  --output-format stream-json --verbose \
  '调用 run_dcf(ticker="600519.SS")，不带任何假设参数'
```

### 现象

init 事件显示 MCP 连接正常：

```json
"mcp_servers": [{"name": "valuescope", "status": "connected"}]
```

`ToolSearch` 返回：`Found 1 tool(s). Use DeferExecuteTool to invoke them.`

随后 `DeferExecuteTool` 调用被拒：

```
Error: Permission to use DeferExecuteTool has been denied because this tool
requires approval but permission prompts are not available in non-interactive
mode. ... To allow this tool, the user can either: (1) re-run with codebuddy -p -y
... or (2) add "DeferExecuteTool" to the "permissions.allow" list in settings.
```

专家按其设计约束（禁止以手算或网络搜索结果替代引擎计算）拒绝伪造估值，最终无产出。

### 对照实验

| 运行条件 | run_dcf 是否成功 |
|---|---|
| 默认权限 | ❌ DeferExecuteTool 被拒 |
| `--permission-mode dontAsk` | ❌ 同上 |
| `--permission-mode auto` | ❌ 同上 |
| settings 中 allow `mcp__valuescope__run_dcf` | ❌ 同上（放行对象错误） |
| **settings 中 allow `DeferExecuteTool`** | ✅ **成功，8 轮完成** |
| 包内自带 settings.json / plugin.json.permissions | ❌ 被忽略，仍被拒 |

最后一行是关键：**该权限只能由运行侧配置，专家包无法自行声明**（这与
"开发者不可自行添加 tools，所有工具权限由系统统一分配" 的规范一致）。
